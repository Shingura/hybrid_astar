# 栅格 A* 寻路：从一张商场平面图开始

## 引子

深夜的商场快关门了，你在 1 号门（起点），想去 18 号铺买奶茶（终点），中间隔着一排关掉的店铺（墙）。怎么走最快？

直觉上你会这样做：站在每个路口掂量两件事——**"我已经走了多远"**和**"目测奶茶店还有多远"**，然后往"加起来最划算"的方向走。

A* 就是把这套直觉变成程序的算法。下面按我们真实的实现顺序，把整个过程（包括踩坑）讲一遍。

---

## 第一幕：把商场画成格子

程序不认识商场，只认识数据。第一件事是造一个 `GridMap`：12 行 20 列的网格，`0` 是能走的地板，`1` 是关掉的店铺。坐标约定 `row` 向下、`col` 向右。地图存在文本文件里，`#` 是墙、`.` 是空地，程序逐行读进来。

> **坑 1**：第一版解析用 `stringstream >>` 读行，打印出来一片空白。原来 `>>` 是"按空白分词读单词"，而地图行 `##########` 中间没有空格，被整行读成一个"单词"，一个格子都没解析出来。改成 `for (char c : line)` 逐字符读才好。
>
> **教训**：`>>` 读的是"单词"，不是"字符"。

---

## 第二幕：一台会自动排序的叫号机

搜索中会不断发现新路口。每个路口记三笔账：

- `cost_so_far_`：从 1 号门**实际**走到这花了几步（经典记号 g）——沿父节点逐格累加，绕过多少弯都算数
- `estimated_cost_to_goal_`：**目测**到奶茶店还有几步（h）——曼哈顿距离，横差加纵差
- `estimated_total_cost()`：两笔之和（f）——"走这条路全程大概几步"，用来排序

**为什么"目测"可以放心无视墙？** 曼哈顿距离假设前面一马平川，所以它是真实剩余代价的**下限**，永不悲观。"永不高估"（可采纳性）正是 A* 找到最短路的数学保证。

路口越发现越多，每轮要挑 f 最小的继续走——这就是 `std::priority_queue`，一台自动排序的叫号机。

> **坑 2**：这台机器默认把**最大**的放队首（大顶堆），而我们要 f **最小**的先出。解法是自定义比较器，且里面要写 `>`：
> ```cpp
> bool operator()(const Node& a, const Node& b) const
>     { return a.estimated_total_cost() > b.estimated_total_cost(); }
> ```
> 记法：比较器回答的是"**谁该沉底**"，符号方向与期望的弹出顺序相反。
>
> **坑 3**：取号要两步——`top()` 看队首，`pop()` 删掉它，没有一步到位。

---

## 第三幕：开始找路

三件装备：

| 装备 | 代码 | 作用 |
|---|---|---|
| 待办清单 | open list（优先队列） | 已发现、待处理的路口，按 f 排序 |
| 已去名册 | closed 表（bool 二维数组） | 处理过的路口打勾，不去第二次 |
| 一沓纸条 | parent 表（坐标二维数组） | 每个路口贴一张："我从哪个路口来" |

行动流程（主循环）：

> 从清单撕下 f 最小的路口 → 是奶茶店就收工 → 名册上已打勾（过期副本）就扔掉换下一张 → 否则打勾，然后站在路口上下左右张望：能走的方向，算两笔账、贴纸条、写进待办清单。重复，直到撕到奶茶店（成功）或清单撕完（失败）。

**要不要一开始就给全商场 240 个格子建好 Node？** 不用，也不能。`cost_so_far_` 取决于沿哪条路走来，只有真实走到某路口隔壁的那一刻才能记账。Node 在"发现邻居的现场"才出生——搜索的波浪推到哪，哪里的 Node 才创建。被墙围死的区域，一辈子没有 Node。这就是 A* 省力气的**惰性**。

**"平行生长"是什么？** 新邻居不是立刻追下去，而是**回炉**进清单重新排队。下一轮撕下来的可能不是刚才的邻居，而是十步前路过、一直躺在清单里的旧路口。没有任何代码写"换路"，那只是排序的自然结果。

> **坑 4**：`numeric_limits<int>::infinity()` 对 int 返回 **0**——"尚未到达"的标记悄悄变成了起点的专属值 0。int 没有无穷大，用 `numeric_limits<int>::max()`。
>
> **坑 5**：parent 表只声明类型没开尺寸，`parent[r][c]` 直接越界。三张表都要按地图尺寸初始化。
>
> **坑 6**：邻居判断写成 `isObstacle(...)` 少了 `!`，变成"只往墙里走"。取反类 bug 编译器不报警，全靠跑出来抓。
>
> **坑 7**：非 void 函数成功/失败两条路都没 `return`，不只是警告，是未定义行为。

---

## 第四幕：绕路的幽灵

第一版跑通了，路也绕过了墙——但仔细看，路径在平地上拐了个 2 步的小弯，不是最短。

元凶是**一个路口会被两条路先后发现**。比如路口 C：沿直线走来是 3 步（好路），从下面绕上来是 5 步（差路）。关键在时序：

1. 清单按 f 排序，不是按 g。差路那条支线只要"目测更近"，f 就可能打平，照样获得生长机会
2. 旧代码里，parent 纸条**谁发现谁写，后到者覆盖先到的**
3. C 被盖章（进 closed）后，纸条就永远锁死了

于是 C"已入队、未盖章"的窗口期内，差路把纸条改写成"我从绕路的 D 来"。回溯时自然绕弯。

**解法叫"松弛"（relaxation）**：加一张光荣榜 `best_cost`，记录每个路口目前已知的最好成绩。新发现的路口先比成绩——赢了才改写纸条、更新成绩、入队；输了直接丢弃。从此纸条只被更好的路改写。

---

## 第五幕：倒着走出商场

找到奶茶店后，路在哪？在纸条里。从奶茶店开始：看纸条"我从 X 来"→ 走到 X → 看 X 的纸条 → …… 一路问到 1 号门。注意**这不是遍历整张表**，是顺着线索追坐标链，每步只查一次表。收集到的坐标是反的（终点→起点），`std::reverse` 翻正。

> **坑 8**：第一版回溯里，查完纸条忘了"移动脚步"（更新当前位置），程序永远站在奶茶店门口自问自答——死循环。

---

## 尾声：验收

一条合格的路径要满足：

- 相邻坐标都只差一格（连续）
- 不经过任何 `1`（不穿墙）
- 长度 = 起终点曼哈顿距离（四邻域的最优下界）

我们的最终成果：从 (1,1) 到 (10,18)，路径绕过商铺排，26 步——正好等于曼哈顿距离，理论最优。

**一句话总结 A\***：所有候选路口平铺在一台自动排序的叫号机里，每轮叫 f 最小的长一步，长完回炉；光荣榜保证每个路口只记录最好的走法；找到终点后顺着纸条倒着走回起点。
